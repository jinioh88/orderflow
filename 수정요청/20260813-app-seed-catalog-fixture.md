# 로컬 시드 데이터 확충 요청 — 카탈로그 화면 검증에 필요한 최소 조건

- status: 완료
- 요청 세션: app
- 요청일: 2026-08-13
- 대상 API: 없음 (API 변경 요청 아님 — **로컬 시드 스크립트** `server/scripts/seed-local.sh` 대상)
- 관련 스토리: US-CAT-01 (카탈로그 조회), 리뷰 게이트 CAT-A

## 현재 상태

현재 로컬 DB의 상품은 **3건**이다 (본죽 쌀 20kg / 일회용 용기 500개 / 한정 김치 5kg).
`GET /products`가 `totalPages: 1`을 돌려주므로 **페이징이 한 번도 일어나지 않는다.**

## 요청 내용

시드 스크립트가 만드는 상품을 아래 조건을 만족하도록 늘려 달라. 수량·품명은 자유다.

| 조건 | 최소치 | 이유 |
|------|--------|------|
| 상품 건수 | **25건 이상** | 페이지 크기 20 → 2페이지 이상이어야 무한 스크롤이 발생한다 |
| 한정 품목 (`limited: true` + `availableQty`) | 2건 이상 | 한정 뱃지·잔여 수량 표시 검증 |
| 카테고리 종류 | **3종 이상** | 카테고리 칩(3.2.11) 검증 — 지금은 2종뿐이라 칩 동작을 구분해 보기 어렵다 |
| 판매중지 (`status: SUSPENDED`) | 1건 이상 | 앱은 `status=ON_SALE`로만 조회한다. 제외가 실제로 되는지 확인하려면 제외될 대상이 있어야 한다 |
| 한 카테고리는 판매중지 상품만 갖게 | 1종 | 3.2.11이 "판매중 상품이 있는 카테고리만" 돌려주는 규칙(서버 결정)을 앱에서 확인 |

- 전부 **점주 계정(`owner@orderflow.local`)과 같은 테넌트**여야 한다.
- 품명은 검색 검증을 위해 서로 구분되는 편이 좋다 (예: 같은 접두어 + 번호).

## 사유

**CAT-A 리뷰 게이트의 잔여 확인이 데이터 부족으로 막혀 있다.** 셀프 리뷰에서 고친 결함 2건 중
하나가 특히 그렇다:

> 첫 페이지가 화면을 못 채우면 스크롤이 불가능해져 다음 페이지를 영영 못 받던 문제

이 수정은 **2페이지 이상 데이터가 있어야** 실기기(실화면)에서 확인할 수 있다. 현재는 회귀 테스트
(가짜 어댑터)로만 검증된 상태이고, 게이트가 "코드보다 동작으로 보여준다"를 요구하므로
(공통 규칙 11) 지금 데이터로는 게이트를 채울 수 없다.

부수적으로 카테고리 칩 태스크도 지금 착수 가능해졌는데(3.2.11 확정), 카테고리가 2종뿐이라
"칩을 눌러 목록이 좁혀지는" 동작을 의미 있게 확인하기 어렵다.

## 참고 — 앱 세션이 확인한 것

- `수정요청/20260813-app-bearer-token-not-verified.md`의 위조 토큰 문제는 **앱 쪽에서도 해결 확인**했다.
  `Bearer x` → `401 UNAUTHORIZED` (이전 200). 처리 결과 기록만 남은 것으로 보인다.
- 3.2.11(카테고리 목록) 신설 확인했다. 앱의 카테고리 칩 태스크 보류를 해제하고 착수한다.
  회신에 적힌 "카테고리 문자열 미정규화(끝 공백이 별개 칩)" 주의사항도 접수했다.

### 반영 결과 — 요청 조건표 전부 충족

시드 스크립트가 만드는 상품을 3건 → **26건**으로 확충했다. 클린 상태(스키마 재적용 → 기동 → 시드)에서
스크립트를 완주시키고, **점주 계정(`owner@orderflow.local`)으로 실제 API를 호출해 측정한 값**이다:

| 조건 | 요청 최소치 | 실측 | |
|------|------------|------|---|
| 상품 건수 | 25건 이상 | **26건** (판매중 23 / 판매중지 3) | ✅ |
| 한정 품목 | 2건 이상 | **3건** — P003(50) · P020(30) · P024(20) | ✅ |
| 카테고리 종류 | 3종 이상 | **4종 저장**, `GET /products/categories`는 **3종 반환** | ✅ |
| 판매중지 | 1건 이상 | **3건** — P009 · P025 · P026 | ✅ |
| 한 카테고리는 판매중지만 | 1종 | **단종예정** (ON_SALE 0건 / 전체 2건) | ✅ |
| 점주와 같은 테넌트 | — | `tenantId=1` (본죽F&B) | ✅ |

### 무한 스크롤 — 실제로 2페이지가 된다

앱 기준(`status=ON_SALE`, `size=20`)으로 확인:

```
GET /products?status=ON_SALE&size=20        → totalPages=2, items 20건
GET /products?status=ON_SALE&size=20&page=1 → items 3건
```

CAT-A 게이트의 "첫 페이지가 화면을 못 채우면 다음 페이지를 영영 못 받던 문제" 수정을
실기기에서 확인할 수 있는 조건이 갖춰졌다.

### 카테고리 칩 검증 조건

```
GET /products/categories → ["냉동식품","부자재","원재료"]
```

**"단종예정"이 빠져 있는 것이 정상이다** — 판매중 상품이 0건이라 3.2.11 규칙대로 제외된다.
칩을 눌렀을 때 목록이 좁혀지는 것도 카테고리별로 확인된다 (ON_SALE 기준 원재료 8 · 부자재 8 · 냉동식품 7).

### 검색 검증용 접미어

품명 끝에 `#01`~`#26`을 붙였다. 요청서의 "같은 접두어 + 번호"를 품명 뒤에 둔 형태다 —
앞에 붙이면 목록 화면에서 품명이 전부 비슷해 보여 시각 확인이 어렵기 때문이다.

```
keyword="#0"  → 9건   (#01~#09)
keyword="#07" → 1건
keyword="만두" → 3건   (김치/고기/새우만두 — 일반 검색도 의미 있게 동작)
```

### 재시드 방법 (주의 — 기존 데이터 삭제)

스크립트는 **재실행이 불가능하다** (이메일·품목코드 중복으로 실패). 다시 넣으려면 초기화가 필요하다:

```bash
docker exec -i orderflow-mysql mysql -uorderflow -porderflow-local orderflow \
  < server/infra/src/main/resources/db/schema.sql   # DB 초기화
SYSTEM_ADMIN_EMAIL=... SYSTEM_ADMIN_PASSWORD=... ./gradlew :api:bootRun   # SYSTEM 계정 재생성
SYSTEM_ADMIN_EMAIL=... SYSTEM_ADMIN_PASSWORD=... SEED_PASSWORD=... ./scripts/seed-local.sh
```

**임시 비밀번호 계정(`owner-temp@orderflow.local`)의 비밀번호는 재시드할 때마다 바뀐다** —
스크립트 실행 결과 출력에서 확인해야 한다 (등록 응답에서 1회만 노출, 스펙 2.4.9).
